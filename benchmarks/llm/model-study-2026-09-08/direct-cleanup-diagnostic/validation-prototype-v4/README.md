# Source validator v4: escaped and multiline payload protection

- **Version:** 4.0
- **Date:** 2026-09-08
- **Status:** Superseded

The frozen v4 source hash is `5f871555c86441d581650e280da676c9396a3d23f27b754c6cfd5d4e61fda6d9`. This revision corrects source-review reproductions in v3: escaped quotes, backslash parity, and multiline/unterminated quoted and inline-code payloads. It introduces no new deletion or semantic rules. [v3-to-v4.patch](v3-to-v4.patch) contains the complete policy/test diff.

Quoted backslash escapes are consumed together; odd backslash runs escape a delimiter and even runs do not. Quotes and inline code protect through newlines and to EOF when unterminated. Quote-style normalization requires an unescaped final delimiter, preserving exact inner content and contractions.

All **22 authored test groups pass**. Replaying the same **567 development proposals** through v4 yields exactly the same delivered outputs as v3, and all 567 independent UTF-8 reconstructions pass. See [unit-tests.txt](unit-tests.txt), [review.json](review.json), and [summary.json](summary.json). No inference or release250/restart12 data was used.

A subsequent authored source-review probe exposed another code-delimiter limitation: `Keep ``um uh`` intact.` could become `Keep ```` intact.` because the regex recognized two empty single-backtick spans. Qualification was paused before launch. This frozen v4 is retained as evidence and superseded by the [v5 delimiter-scanner correction](../validation-prototype-v5/README.md).
